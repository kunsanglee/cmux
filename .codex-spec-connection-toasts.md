# Task: Route iOS connection statuses through the toast system

Branch: feat-ios-connection-toasts (this worktree). Do NOT commit; leave changes uncommitted for review.

## Goal

When the Toasts beta flag is ON (`ToastCenter.isEnabled`), the two heavyweight
connection surfaces in the workspace detail must stop rendering and every
connection status change (reconnecting, disconnected, connection lost, account
mismatch, reconnected) must surface through `CmuxMobileToast` instead. When the
flag is OFF, behavior stays byte-for-byte legacy (current banners/overlay).

The two surfaces to retire behind the flag (see screenshot complaint: both
stack on top of each other over the terminal):

1. `Packages/iOS/CmuxMobileShellUI/Sources/CmuxMobileShellUI/MobileConnectionRecoveryOverlay.swift`
   — the floating top pill (`MobileConnectionRecoveryBanner`, non-inline
   variant) shown via `.mobileConnectionRecoveryOverlay(...)` on
   `WorkspaceDetailView` (both `#if os(iOS)` and `#else` branches).
2. `Packages/iOS/CmuxMobileShellUI/Sources/CmuxMobileShellUI/TerminalDisconnectedOverlay.swift`
   — the fullscreen "Disconnected / Reconnect" overlay mounted in
   `WorkspaceDetailView.detailContent()`.

Do NOT touch the inline list variants (`rendersInline: true` in
`WorkspaceListView.swift` / `WorkspaceListTableCoordinator.swift`) or
`MobileMacConnectionStatusRow` — those are list rows, they stay.

## Design (follow exactly)

### 1. ToastCenter: dismiss by coalescing key

In `Packages/iOS/CmuxMobileToast/Sources/CmuxMobileToast/ToastCenter.swift` add:

```swift
/// Dismiss any toast carrying `coalescingKey`, visible or queued. Used when
/// the condition a persistent/status toast describes stops being true.
public func dismiss(coalescingKey: String)
```

Visible match → `dismissCurrent()` (queue advances). Also drop queued matches.
Add Swift Testing coverage in
`Packages/iOS/CmuxMobileToast/Tests/CmuxMobileToastTests/ToastCenterTests.swift`
following the existing ManualClock patterns: dismissing the visible toast by
key advances the queue; dismissing a queued toast by key drops only it; a
non-matching key is a no-op.

### 2. Shared connection toast vocabulary

New file `Packages/iOS/CmuxMobileShellUI/Sources/CmuxMobileShellUI/ConnectionStatusToasts.swift`:

```swift
extension Toast {
    /// One capsule for every connection-status notice: newer states replace
    /// the visible one in place instead of queueing a parade.
    static let connectionStatusKey = "connection.status"

    static func connectionReconnecting() -> Toast   // .info, systemImage "arrow.triangle.2.circlepath", default dwell
    static func connectionUnavailable(reconnect: @escaping @MainActor @Sendable () -> Void) -> Toast
        // .failure, title = existing L10n "mobile.connection.unavailable" ("Disconnected"),
        // message = NEW key mobile.connection.toast.unavailableMessage
        //   en "The live connection dropped. Your Mac may still be online."
        //   (ja translation too), action label = existing "mobile.workspace.reconnect" ("Reconnect")
    static func connectionLost(retry: @escaping @MainActor @Sendable () -> Void) -> Toast
        // .failure, title existing "mobile.recovery.lost" ("Connection lost"),
        // message existing "mobile.recovery.lostDescription", action existing "mobile.recovery.retry"
    static func connectionReauthRequired(message: String?, signOut: (@MainActor @Sendable () -> Void)?) -> Toast
        // .failure, message = provided connectionError ?? existing "mobile.recovery.accountMismatch",
        // action = existing "mobile.recovery.switchAccount" when signOut != nil,
        // autoDismiss: .never (must-acknowledge state; the only .never in this change)
    static func connectionReconnected() -> Toast
        // .success, existing "mobile.connection.reconnectedToast"
}
```

All use `coalescingKey: Self.connectionStatusKey`. Reconnecting message:
reuse existing key "mobile.recovery.reconnecting" ("Reconnecting…").

### 3. Recovery-state bridge (replaces the floating pill)

In `MobileConnectionRecoveryOverlay.swift`: derive an equatable phase from the
store, mirroring the banner's existing priority order:

```swift
enum ConnectionRecoveryToastPhase: Equatable {
    case reauth(message: String?)
    case lost
    case recovering
    case idle

    static func derive(requiresReauth: Bool, recoveryFailed: Bool, isRecovering: Bool, connectionError: String?) -> Self
}
```

Modifier behavior:
- `toasts.isEnabled == false`: render the legacy banner exactly as today.
- `toasts.isEnabled == true`: render no chrome; instead
  `.onChange(of: phase, initial: true)` presents the matching toast
  (`connectionReauthRequired` / `connectionLost` / `connectionReconnecting`);
  on `.idle` it calls `toasts.dismiss(coalescingKey: Toast.connectionStatusKey)`
  ONLY when the previous phase was `.reauth` (the reauth toast is `.never`
  and must clear when the state resolves; transient phases resolve through
  the connected-transition path in item 5 or dwell out on their own).
  Keep retry/signOut closures identical to the legacy banner
  (`store.retryMobileConnection()`, the passed `signOut`).

`ConnectionRecoveryToastPhase` and its `derive` go in
`ConnectionStatusToasts.swift` so they are unit-testable. Add tests in
`Packages/iOS/CmuxMobileShellUI/Tests/CmuxMobileShellUITests/ConnectionStatusToastsTests.swift`:
derive priority (reauth beats lost beats recovering beats idle), and the toast
factories carry the shared coalescing key / expected style / action label
presence / reauth-is-never-dismissing.

### 4. Terminal status bridge (replaces the fullscreen overlay)

In `WorkspaceDetailView.detailContent()`:
- Extract the existing Reconnect closure (the `Task { switchToMac ?? reconnectOrRefresh }`
  body currently inline in `TerminalDisconnectedOverlay`'s `reconnect:`) into a
  private method `reconnectToWorkspaceMac()` used by both paths.
- Gate the overlay: `if !toasts.isEnabled && connectionStatus != .connected { TerminalDisconnectedOverlay(...) }`.
- Add `.onChange(of: connectionStatus, initial: true)` (iOS and macOS both —
  attach it where `detailContent` is composed, once): when `toasts.isEnabled`:
  - `.unavailable` → `toasts.present(.connectionUnavailable(reconnect: ...))`
  - `.reconnecting` → `toasts.present(.connectionReconnecting())`
  - `.connected` → `toasts.dismiss(coalescingKey: Toast.connectionStatusKey)`
    (the celebratory success toast stays owned by WorkspaceShellView, item 5)
- Keep `MobileMacConnectionStatusPill` mounted as-is, but when
  `toasts.isEnabled` pass it a new optional `reconnect` closure (same
  `reconnectToWorkspaceMac`); the pill becomes a Button when the closure is
  non-nil AND status == .unavailable, so a durable reconnect affordance
  remains after the toast dwells out. Flag off → pill unchanged (display-only).
  Keep its accessibility identifier; add `.accessibilityHint` naming the
  reconnect action when tappable.

### 5. Reconnected success + stale-capsule cleanup

In `WorkspaceShellView.swift` (`.onChange(of: store.connectionState, initial: true)`
around line 335): when state becomes `.connected`, first
`toasts.dismiss(coalescingKey: Toast.connectionStatusKey)` unconditionally,
then present the success toast only `if hasHeldConnection` — switch it to the
shared factory `.connectionReconnected()` (which now carries
`connectionStatusKey` instead of "connection.reconnected").

### 6. Localization

New key(s) (at minimum `mobile.connection.toast.unavailableMessage`) go into
`ios/cmux/Resources/Localizable.xcstrings` with BOTH en and ja values,
matching the file's existing JSON shape. Reused keys need no edits. Audit:
every string in the new code paths must come through `L10n.string`.

## Constraints

- Never-dismiss toasts: ONLY the reauth toast may use `.never` (queue-starvation:
  a visible `.never` toast blocks the FIFO queue). Disconnected/lost use the
  default action dwell; reconnecting/reconnected use their style defaults.
- No `useEffect`-style scattered logic: keep the bridges in the two modifiers
  described above, nothing in row/list code.
- No `DispatchQueue.asyncAfter`, no sleeps. All timing stays inside ToastCenter.
- Swift 6 concurrency: package code compiles under the packages' existing
  settings; toast action handlers are `@MainActor @Sendable`.
- Match surrounding code style and comment density. Comments explain
  constraints, not narration.
- Do not rename/remove existing accessibility identifiers on legacy paths.
- Do not touch `Localizable.xcstrings` entries other than adding new keys.
- Do not edit anything under `Sources/` (macOS app), `ghostty/`, `web/`.
